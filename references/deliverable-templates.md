# 交付物模板库

各步骤交付物的标准骨架。按需取用，不要为了填满模板而写废话。

---

## 待确认需求清单

```markdown
## 【交付物：待确认需求清单】

### 已明确
| 维度 | 内容 |
|---|---|
| 业务目标 | |
| 技术栈 | |
| 使用场景 | 个人demo / 内部工具 / 生产服务 |
| 交付形态 | CLI / Web / API / GUI / 库 |

### 待确认（请回答）
1. 【问题】—— 为什么需要确认（影响什么决策）
2. ...

### 已推断（如不认可请指出）
- 推断：xxx，依据：目录下已有 package.json 表明是 Node 项目
```

**要求**：问题不超过 6 个，每个说明「为什么要问」。不要罗列 20 条让人放弃回答。

## 技术方案文档

```markdown
## 【交付物：技术方案文档】

### 1. 整体架构
（结构图或分层描述）

### 2. 模块拆分
| 模块 | 职责 | 依赖 |
|---|---|---|

### 3. 接口定义
```
POST /api/xxx
req:  { field: type, ... }
resp: { code, data, message }
err:  400 参数错误 / 401 未授权 / 500 内部错误
```

### 4. 存储方案
表结构 / 文件结构 / 缓存策略

### 5. 异常与容错
- 超时：3s，重试 2 次，指数退避
- 降级：xxx 不可用时返回缓存
- 事务：xxx 操作放在同一事务

### 6. 依赖清单
| 依赖 | 版本 | 用途 | License |
|---|---|---|---|

### 7. 设计取舍
| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. xxx | | | **采用** |
| B. yyy | | | 否，因为... |

### 8. Git 分支规划
- 开发分支：feature/xxx
- 合入目标：dev
- 预计提交数：N
```

**第 7 节是灵魂**。没有取舍说明的方案等于「我想这么干，别问为什么」。

## 自测结果报告

```markdown
## 【交付物：自测结果报告】

### 测试环境
OS / 运行时版本 / 依赖版本

### 用例执行
| 用例 | 类型 | 结果 |
|---|---|---|
| 正常登录 | 主流程 | ✅ |
| 空密码 | 边界 | ✅ |
| 超长用户名(10万字符) | 异常 | ❌ 见 BUG-0001 |

### 实际输出
```
$ pytest -q
============ 12 passed, 1 failed in 0.84s ============
```

### 发现的缺陷
| 单号 | 标题 | 优先级 |
|---|---|---|
| BUG-0001 | 超长用户名导致内存溢出 | P1 |
```

**必须贴真实命令输出**。「测试通过」四个字不算自测。

## 风险清单

```markdown
## 【交付物：风险清单】

| # | 维度 | 风险描述 | 等级 | 缓解措施 |
|---|---|---|---|---|
| 1 | 性能 | 单表数据超百万后查询变慢 | 【中风险】 | 加索引 + 分页 |
| 2 | 安全 | token 存 localStorage 有 XSS 风险 | 【高风险】 | 改 httpOnly cookie |
| 3 | 兼容 | 依赖 Node 20，低版本不兼容 | 【低风险】 | 文档注明要求 |

### 缺陷门禁校验
- 未关闭 P0：0
- 未关闭 P1：1（BUG-0005）
- **结论：【高风险】** 建议修复 BUG-0005 后再上线；如需放行，理由：影响面仅限后台管理页
```

## 复盘纪要

```markdown
## 【交付物：复盘纪要】

**版本**：v1.2.0
**周期**：
**参与**：

### ✅ 本次收获
1. **选型**：xxx 比 yyy 更适合，因为...
2. **调研**：发现 lib-a 的 xxx 设计可直接借鉴
3. **架构**：把 token 刷新抽成独立模块，后续换方案只改一处
4. **规范**：Conventional Commits 让 CHANGELOG 自动生成省了手工整理

### ⚠️ 失误与改进
| 失误 | 影响 | 改进措施 |
|---|---|---|
| 需求阶段没问清并发量 | 方案按单机设计，后期返工 | 需求清单加「预估 QPS」必填项 |
| 自测只覆盖主流程 | 空数组场景漏测，P1 缺陷 | 测试用例必须含边界三类 |

### 🐛 缺陷根因分析
| 单号 | 标题 | 根因 | 改进 |
|---|---|---|---|
| BUG-0001 | 空数组越界 | 编码疏漏 | 加参数校验 + 补单测 |

**根因分布**：编码疏漏 2 / 测试漏测 1 → 下轮重点补单测覆盖

### 下轮待办
- [ ] 补并发压测
- [ ] 建立边界用例模板
```

**禁止**写「本次顺利完成，无问题」。找不出失误，说明复盘没做，不是项目没毛病。
